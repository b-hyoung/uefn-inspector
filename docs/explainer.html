에디터를 안 켜고 레벨을 읽는다

기본 MCP는 언리얼 에디터가 살아 있어야 뭔가를 읽습니다. 우리가 만든 도구는 디스크의 .uasset 파일을 직접 파싱해서, 에디터가 꺼져 있어도 — 혹은 다른 작업 중이어도 — 레벨에 뭐가 배치됐는지 읽어냅니다. 이 문서는 "무엇을, 어떻게, 왜"를 그림으로 설명합니다.

1무슨 차이가 있나

같은 "읽기"인데, 읽는 위치가 다릅니다.

● 기본 MCP

살아있는 에디터에 물어본다

  • 언리얼이 켜져 있어야 함
  • 리플렉션으로 메모리의 오브젝트를 조회
  • 편집 중이면 경합 · 무거움
  • Verse-VM 내부 설정은 못 읽음(그 벽)
● 우리 도구 (오프라인)

파일을 직접 뜯어 읽는다

  • 에디터 꺼져 있어도 OK
  • 디스크의 .uasset 바이트를 파싱
  • 병렬 가능 · 작업과 동시에
  • 파일에 저장된 건 다 보임(값 해석은 별개)

2어떻게 읽나 — 3개의 표

하나의 .uasset 파일은 안에 "표(table) 3개"를 품고 있습니다. 그걸 순서대로 파싱하면 인벤토리가 나옵니다.

입력
.uasset 파일
배치된 액터 1개 = 파일 1개 (UEFN OFPA 방식)
→
파싱
표 3개
Name표164
Import표49
Export표22
→
출력
인벤토리
배치 디바이스 + 참조 에셋 목록

Name표 = 파일이 쓰는 모든 이름(문자열).   Import표 = 이 파일이 바깥에서 가져다 쓰는 것(클래스·사운드 등).   Export표 = 이 파일 안에 들어있는 오브젝트들.

예: Import에서 Device_CRD_AudioPlayer_C 클래스를, Name에서 /MyProject/Audio/Heartbeat_Near 사운드를 뽑아냅니다.

3파일 안 지도 — serial_offset이 뭔가

4지금(A) 읽기 · 나중(B) 쓰기

지금은 A(읽기)만 만들지만, 리더가 위 "바이트 주소"를 들고 있어서 나중에 B(쓰기)를 재작업 없이 얹을 수 있습니다.

A · 읽기 (지금 · 완료)
파일→모델→리포트
  • 67개 액터 파일 10ms에 파싱
  • 벽 46 · AudioPlayer 3 · 심박음 3단 다 잡힘
  • 에디터 없이 · 병렬로
B · 쓰기 (미래 · 자리만)
모델→수정→되쓰기
  • serial_offset로 "여기 고친다"를 짚음
  • 표준 프로퍼티 편집 + 라운드트립 가능
