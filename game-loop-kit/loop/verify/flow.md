# 플로우 검증 — 맵 → 게임 → 플레이어들이 실제로 어떻게 노는가

목적: 맵(구역)·게임(규칙)·플레이어 플로우(단계)가 맞물리는지, 그리고 **여러 플레이어가 어디서 만나 어떤 재미가 생기는지**를 표로 미리 보고, 끝난 뒤에는 로그로 설명한다. 설명 못 하는 구간은 재미 공백이며 다시 만든다.
시점: ① 인테이크 끝(종이) → DOR 조건 · ② 뼈대 티켓 뒤(`level_map` 좌표) → 티켓 1 수용 · ③ 레벨 완료 후 **플로우 리포트**(§6) → 레벨 `done` 조건 · ④ ⑤판정에서 4레벨 리포트 비교.

## 1. 단일 플로우 표 (역할 하나의 한 판)
| 단계 | 자리(구역/좌표) | 아는 것 | 결정(무엇 사이) | 발동 규칙/디바이스 | 재미 층(표/중/심/메타) | 관측 지표 |
|---|---|---|---|---|---|---|
| S0 스폰 | | | | | | |
| S1 첫 결정 | | | | | | |
| Sn 종료/재스폰 | | | | | | |
한 줄 = 플레이어 상태가 바뀌는 순간. 걷기 구간은 줄 사이 "이동 <초>"로 적는다.

## 2. 다인 플로우 표 (멀티의 재미는 여기서 보인다)
역할(술래/도망자, 팀 A/B, 동일 역할 N명)마다 §1을 만든 뒤 시간축으로 겹친다.
| t(초) | 역할A 자리·행동 | 역할B 자리·행동 | 만남(같은 자리/시야/소리) | 상호작용 종류 | 이 순간의 재미(누구에게, 왜) | 지표 |
|---|---|---|---|---|---|---|
상호작용 종류: 충돌(교전) · 회피/추격 · 정보 비대칭(한쪽만 앎) · 기만(미끼·블러프) · 협동(둘이어야 됨) · 방해 · 역전 · 관전(죽은 뒤). 재미는 "A는 B가 오는 줄 모르고 B는 안다 → B의 긴장, A의 의심"처럼 **양쪽** 관점으로 쓴다.

## 3. 대조 규칙 (fail 조건)
| # | 검사 | fail |
|---|---|---|
| F1 | 모든 규칙이 표의 어느 줄에서 발동하는가 | 자리 없는 규칙 |
| F2 | 모든 구역(MAP)이 어느 줄에서 쓰이는가 | 규칙 없는 구역(배경 강등 또는 삭제) |
| F3 | 줄마다 결정이 있는가 | 결정 없는 줄 연속 2개(걷기 게임) |
| F4 | 중층·심층이 각각 1줄 이상에 붙는가 | 표층만 |
| F5 | 긴장 최고점 줄이 비틀기와 같은 자리인가 | 비틀기가 플로우에 없음 |
| F6 | 모든 지표가 어느 줄에서 관측되는가 | 관측 자리 없는 지표(B-0 Blocker) |
| F7 | 스폰→첫 결정 시간이 MAP §크기와 맞는가 | 이동만 <n>초 이상(GDD §0 확정값) |
| F8 | 종료 줄에서 승/패/재스폰이 닫히는가 | 끝나지 않는 플로우 |
| F9 | 재스폰 후 어느 줄로 돌아오는가 | 재진입 규칙 없음 |
| F10 | N명일 때 같은 자리에 몰리는 줄이 의도인가 | 의도 없는 병목 |
| F11 | §2에 만남 줄이 첫 결정 이후 <n>초 안에 있는가 | 서로 안 만남 = 솔로 게임 N개 |
| F12 | 상호작용 종류가 2가지 이상인가 | 교전만 반복 |
| F13 | 한쪽의 결정이 다른 쪽의 상황을 바꾸는 줄이 있는가 | 서로 영향 없음(병렬 플레이) |
| F14 | 죽거나 기다리는 동안의 줄이 있는가(관전·재진입·역할 전환) | 대기 시간이 빈 줄 |
| F15 | 뒤처진 쪽이 따라잡는 줄이 있는가(D·E 팩) | 첫 우위가 끝까지 감 |
| F16 | 만남 줄마다 재미가 양쪽 관점으로 적혀 있는가 | 한쪽만 재미(다른 쪽은 당하기만) |

## 4. 절차
1. `spec/MAP.md` 구역표와 `GDD`·`systems` 규칙 목록을 놓고 §1을 역할마다, §2를 하나 채운다.
2. F1~F16을 순서대로 돈다. fail은 `spec/MAP.md` 플로우 매트릭스 절에 번호와 사유로 적는다.
3. 처리: F1·F6 스펙 수정 · F2 구역 삭제/강등 · F3·F4·F5 맵 또는 비틀기 재설계 · F7 크기 축소 · F8·F9 규칙 추가 · F11·F13 만남을 만드는 공간/규칙(합류점·목표 공유·소리) 추가 · F12 상호작용 종류 추가 · F14 관전/재진입 규칙 · F15 역전 수단 · F16 당하는 쪽의 결정 추가.
4. ②에서는 자리 열을 `level_map` 좌표로 바꾸고 F7·F11을 실측 거리로 다시 잰다.
5. 결과를 `MAP.md`와 `levels/LEVEL-X/build.md` 구조 절에 기록한다.

## 5. 측정 로그가 표를 따라가게
자동 실행 로그 `[M]`에 단계 번호(`step=S2`)와 만남 이벤트(`meet=A,B loc=…`)를 남긴다. 그래야 §6에서 계획 플로우와 실제 플로우를 대조할 수 있다. 단계 태그 없는 로그는 플로우 리포트를 못 만든다 → 티켓 3(측정 로그) 미완.

## 6. 플로우 리포트 — 끝나면 AI가 설명한다 (레벨 `done` 조건)
`levels/LEVEL-X/flow-report.md`, 자동 실행 N회 로그로 작성한다.
```
## 실제 플로우(계획 대비): S0 → S1(t=<평균>) → … · 계획과 다른 줄: <어디, 왜>
## 만남: 언제(t)·어디·누구·종류 · 계획한 만남 중 안 일어난 것: <F11/F13 재판정>
## 각 줄의 재미 설명(로그 근거): S1 — <누가 무엇을 결정했고 그게 왜 재미인지, 지표 값>
## 재미 공백: 설명이 안 되는 줄 = <Sk> — 원인 가설(자리/규칙/만남/정보) → 재작업 티켓
```
규칙: 재미 설명은 지표 값이나 로그 이벤트를 근거로만 쓴다. 근거 없는 줄은 "재미 있다"가 아니라 **재미 공백**으로 적는다. 공백이 있으면 그 줄을 겨냥한 수정 티켓을 만들어 같은 레벨에서 다시 돌리고, 2회째도 공백이면 레벨 `무효`로 표시하고 다음 레벨로 간다(규칙 0, 사람 호출 없음). 종료 보고에는 4레벨의 플로우 리포트와 공백 목록을 붙인다.

## 7. 예 (스텔스 추격 · 도망자 A / 술래(가드 조종 봇) B)
| t | A | B | 만남 | 종류 | 재미 | 지표 |
|---|---|---|---|---|---|---|
| 0 | 스폰(남서), 목표 방향 봄 | 패트롤(중앙) | 없음 | — | A: 소리로 위치 추정 | — |
| 12 | 중앙 컨테이너, 우회 vs 미끼 결정 | 중앙→북 이동 | 소리 | 정보 비대칭 | A는 B 위치를 알고 B는 모름 → A의 우위감 | 미끼 사용률 |
| 20 | 미끼 발동(북) | 소리 쪽으로 이동 | 시야 | 기만 | A: 예측 적중의 쾌감 / B: 속았음을 뒤늦게 앎 | ambush_window |
| 28 | 역습 or 통과 | 반응 | 충돌 | 역전 | A: 위험 감수 보상 / B: 반격 기회 | reversal_success |
F14: A가 죽은 뒤 줄이 없음 → fail → 관전 시점 규칙 추가.
