# LOOP — 게임 루프 규약

## 하나의 루프 (인테이크도 루프의 한 단계다)

```
        ┌──────────────── THE LOOP ────────────────┐
        │                                           │
  ①인테이크 → ②DOR게이트 → ③분해 → ④레벨×4 → ⑤판정 │
   (캐묻기)   (판단가능?)  (티켓)  (3h씩·리뷰포함) │
        ↑                                           │
        └──── 기각/애매 → 무엇이 틀렸나에 따라 복귀 ──┘
```

**되돌아가는 규칙(⑤ → 어디로):**
| 판정 | 원인 | 복귀 지점 |
|---|---|---|
| **지지** | — | spec에 확정 기록 → **①** 다음 가설(H-NN+1)로 |
| **기각** | 가설이 틀림 | **① 인테이크**(대안 가설 재발굴) → 다시 전체 |
| **애매** | 변주가 부족 | **③ 분해** (축 하나만 바꾼 레벨 추가) |
| **무효** | 측정이 틀림(리뷰 Blocker) | **②** 지표·임계값 수정 후 해당 레벨 재실행 |

> **인테이크는 일회성 준비가 아니다.** 기각될 때마다 돌아오는 **루프의 정식 단계**다.
> 그래서 실험이 한 바퀴 돌 때마다 게임 이해가 깊어진다.

### 두 겹의 안쪽 구조 (④ 안에서)
```
④레벨 하나(Task) = 티켓 4개
   티켓 → 구현 → 구조검증 → 행동검증 → 적대적 빠른공격 → done
   레벨 완료 시 → 적대적 전면공격
```
- **실험층:** `spec/FUN-HYPOTHESIS.md` → `plan/PLAN-NN`(가설) → Task(변주 레벨) → `experiments/EXP-NN-results.md`
- **티켓층:** 아래 "한 반복"

## 🤖 무인 원칙 (사람은 루프 안에 없다)
- 판정은 **규칙 기반 자동** — `FUN-HYPOTHESIS`의 지표·임계값·판정식대로 기계가 결정. 주관 평가 없음.
- 플레이도 **자동 실행**(봇/시뮬레이션 모드) → `levels/*/autoplay.md`. 사람 플레이테스트 없음.
- 사람은 **정지게이트에서만** 호출된다(아래). 그 외엔 개입하지 않는다.
- 자동 실행이 불가능한 메카닉이면 → **자동 구동 모드 구현 티켓**을 먼저 만든다(그게 없으면 루프가 못 돈다).

## 🔁 한 반복
1. **선택** — `plan/PLANS.md` → 우선 Plan → Task → 맨 위 `todo` 티켓(의존성 충족) → `doing`으로.
2. **설계** — 티켓 수용기준을 보고 필요한 Verse 코드 + 디바이스 배치/배선 결정.
3. **구현**
   - Verse: `verse/<file>.verse` 작성/수정 (AI).
   - 디바이스: 표준 배치·값 = **MCP 라이브** / Verse-VM 값·배선 = **uefn-inspector 오프라인 패치**(에디터 OFF, 백업).
   - **새 @editable 슬롯 배선**은 GUI 필요 → 정지게이트. (기존 배선 *변경*은 uefn-inspector 오프라인으로 가능)
4. **구조검증** (uefn-inspector, 에디터 OFF)
   - 배치·배선·설정이 수용기준과 일치? + **선언↔배선 교차검증**(`.verse` @editable ↔ `.uasset` SavedActor).
   - `loop/verify/structural.md`의 레시피 사용.
5. **행동검증** (라이브 PIE)
   - Verse 컴파일(MCP `BuildAll`) → PIE 실행 → `get_editor_log`/상태로 행동수용 확인.
   - `loop/verify/behavioral.md`의 레시피 사용.
6. **적대적 빠른 공격** (2~3분) — `loop/review/ADVERSARIAL.md` A절 3문항.
   *"이 티켓은 재미 판단 가능성에 기여했나?"* Blocker면 `done` 불가.
7. **완료** — 구조·행동·리뷰 셋 다 통과 → 티켓 `done` → 롤업 → `SNAPSHOT` 갱신 → 다음 티켓.
   (Task=레벨 완료 시 **전면 공격** 1회 — B-0 판단가능성 게이트부터)

## ⏱ 시간 예산
레벨(Task) 1개 = **3시간**(A레벨 4시간). 구간별 배분·초과 규칙·세션 로그 → `loop/TIMEBOX.md`.
구간 3·4(측정) 초과는 **즉시 정지게이트** — 측정이 없으면 판단 불가라 시간만 태운다.

## ✅ 착수 전 게이트
레벨 작업 시작 전 **`spec/DOR.md`** 통과 필수(판단 가능성 포함). 미통과면 INTAKE로 되돌아간다.

## 🛑 정지게이트 (멈추고 사람 호출)
- **새 @editable 슬롯** 배선 필요(에디터 GUI만 가능 — 기존 배선 변경은 오프라인 처리)
- **행동검증 3회** 실패 → 원인 요약 보고
- **스펙 모호** / 창작 결정 필요
- **파괴적 작업**(원본 덮기·삭제·기본자산 변경) — 승인 우선
- **새 외부 의존성**(에셋·플러그인)

## 🔬 바깥 루프 한 사이클 (실험)
1. **가설 선택** — `spec/FUN-HYPOTHESIS.md`의 H-NN (지표·판정규칙·변주축 확인)
2. **변주 설계** — 이번 실험에서 **바꿀 축 하나** 결정 → Task(레벨) 2~3개 생성 (`levels/LEVEL-*/build.md`)
3. **각 레벨 빌드** — 안쪽 티켓 루프로 (뼈대 → 배선 → 측정로그 → 자동실행)
4. **측정 수집** — PIE 자동 실행 N회 → 로그 `[M]` 파싱 → `metrics.md` 집계 (`autoplay.md`에 회차 기록)
5. **비교·판정** — `FUN-HYPOTHESIS`의 **판정식 그대로 적용** → **지지 / 기각 / 애매** → `experiments/EXP-NN-results.md`
6. **다음 행동**
   - 지지 → 그 조건을 `spec/GDD.md`·`systems/`에 **확정**으로 기록 → 다음 가설
   - 기각 → 대안 가설로 전환
   - 애매 → **축 하나만** 바꾼 새 변주 레벨 추가

**실험 규율:** 한 실험에서 **한 축만** 변경(교란 방지). 불가피하면 결과 문서에 교란요인 명시.
**지표·임계값·실행 조건은 실험 도중 바꾸지 않는다**(바꾸면 비교 무효 → 새 실험으로).

## 상태 값
`todo` · `doing` · `done` · `blocked`(정지게이트 대기)

## 드리프트 검사 (Hybrid C의 상태-diff)
매 반복 or 주기적으로 uefn-inspector로 **현재 상태 ↔ 스펙** 비교:
- 선언됐으나 미배선 @editable (예: 오디오 슬롯) → 새 티켓 or blocked
- 스펙에 없는 배치 / 스펙과 다른 설정값 → 드리프트 티켓
