# INTAKE — 게임을 캐내는 질문지 (spec을 채우기 전에)

> **용도:** 빈 `spec/`을 채우기 위해 **무엇을·얼마나 디테일하게 물어볼지** 정의한다.
> 이 문서의 답 → `GDD.md`(무엇/왜) → `systems/`(정확한 규칙) → 티켓 배분(`DECOMPOSE.md`).
>
> **출처:** 질문 뼈대는 Claude Code Game Studios 브레인스토밍 워크플로(MIT, 이 저장소의
> game-design-skill 참조자료)를 이 kit에 맞게 적응. MDA·자기결정이론(SDT)은 **설계 렌즈**로
> 사용하며 "재미의 증명"이 아니다.

## 진행 원칙
- **한 번에 하나씩**, 대화로. 체크리스트 낭독 금지.
- 게임 이름을 묻기 전에 **사람(취향·감정)**부터.
- 답이 **설계를 바꾸는 질문만** 한다. 뻔한 건 기본값으로 정하고 통보.
- 각 답은 **어느 문서로 흘러가는지** 표시(아래 "→" 표기).

---

## Phase 1 — 창작 발견 (사람 먼저)
**감정 앵커**
- 게임에서 진짜 몰입했던/짜릿했던 순간은? **무엇이** 그 감정을 만들었나? → GDD §핵심재미
- 늘 원했지만 어떤 게임도 못 준 판타지/파워트립이 있나? → GDD §Core Fantasy

**취향 프로필**
- 가장 오래 한 게임 3개와 **계속 하게 만든 것**은? *(자유 입력)* → GDD §레퍼런스
- 좋아하는/피하는 장르와 이유는? → 안티기둥
- 도전 / 휴식 / 이야기 / 자기표현 중 어느 쪽? *(택1)* → 주요 MDA 미학

**실무 제약** *(한 번에 묶어 질문)*
- **Experience**: 플레이어에게 주고 싶은 경험 (도전·숙련 / 이야기·발견 / 표현·창의 / 이완·몰입)
- **Timeline**: 현실적 개발 기간 (주 / 개월 / 1-2년 / 그 이상)
- **Dev level**: 개발 경험 (첫 게임 / 출시 경험 / 프로)
→ 스코프·티켓 크기 결정

**산출:** 3~5문장 **Creative Brief**.

## Phase 2 — 컨셉 확정
- **한 줄 피치** (10초 테스트 통과?) → GDD §1
- **Core Verb** — 플레이어가 가장 많이 하는 **단 하나의 동작** → 모든 티켓의 기준점
- **Core Fantasy** — 감정적 약속 → GDD §2
- **Unique Hook** — "X 같은데, **게다가** Y" 테스트 통과? → GDD §1
- **가장 큰 리스크** — 아직 답 못 한 가장 어려운 질문 → 프로토타입 티켓 후보

## Phase 2.2 — 게임 **형태** 적합성 ⭐ (가장 먼저 걸러야 할 것)
> 컨셉을 듣자마자 확인한다: **이 형태가 UEFN에 맞나?**
> `UEFN-FEASIBILITY.md` **0단계 표**로 판정 (2D·턴제·RTS·카드·리듬·클릭커…)

- 🟢 3D 슈터/생존/파쿠르/탐험 → 그대로 진행
- 🟡 2D·턴제·카드·리듬 등 → **UEFN식 번역을 먼저 확정**하고 그 번역본으로 계속
  (예: "2D 횡스크롤" → "고정 사이드 카메라 + X축 이동 제한 3D". *픽셀아트는 불가*)
- 🔴 RTS·모바일 클릭커·대규모 오픈월드 → **정직하게 말한다.** 형태를 바꿀지, 다른 엔진을 쓸지 사용자가 결정.
  억지로 진행하지 않는다.
- **흉내의 비용을 숨기지 않는다** — "2D 됩니다"가 아니라 "2D처럼 보이게 되고, 대신 X를 포기한다".
→ 확정된 형태를 `GDD.md §0 확정 프레임`에 기록. 이후 모든 설계가 그 위에서 돈다.

## Phase 2.5 — 장르 팩 선택 ⭐ (질문이 갈리는 지점)
> 게임마다 **잡아야 할 디테일이 다르다.** 컨셉이 나오면 `GENRE-PACKS.md`에서 팩을 고르고,
> 그 팩의 **필수 질문**을 이후 단계에 끼워 넣는다.

- 이 컨셉에 가장 가까운 팩은? (A 전투/슈터 · B 생존/추격 · C 퍼즐/탐색 · D 경쟁/대전 ·
  E 협동 · F 이동/파쿠르 · G 건설/자원) — **하이브리드면 2개까지, 주(主)를 먼저 확정**
- 없으면: 가장 가까운 팩 + 공통 질문으로 시작 → 새 팩을 `GENRE-PACKS.md`에 추가

**공통 질문(팩 전에 항상)**
- 승패·종료 조건 / 세션 길이 / 실패 시 잃는 것(재시작 비용)
- **인원 구조**: 솔로/협동/대전(1v1·NvN)/비대칭 → *4레벨의 인원 축*
- **정보 구조**: 누가 무엇을 아나 (완전정보 vs 불완전정보)

→ 선택한 팩의 **필수 질문 4개**는 Phase 3.5 직후에 이어서 던진다.
⚠️ 장르는 **답이 아니라 질문의 안내자** — 관습 수치를 값으로 가정하지 않는다.

## Phase 3 — 코어 루프 (⭐ "재미가 어디서 오나"의 핵심)
층위별로 **재미의 원천**을 명시. 티켓의 행동 수용기준이 여기서 나온다.
- **30초 루프(순간)**: 코어 액션의 **손맛**은? 무엇이 그걸 기분 좋게 만드나 —
  오디오 피드백 / 시각 juice / 타이밍 / 전술 깊이? → systems/ 수용기준
- **5분 루프(단기)**: "한 판만 더"가 발동하는 지점은? 어떤 선택을 하나?
- **세션 루프(30~120분)**: 한 세션의 모양·자연스러운 종료 지점·안 할 때도 생각나는 훅
- **진행 루프(며칠~주)**: 무엇이 성장하나(파워/지식/선택지/이야기)? 언제 "끝"인가?

**동기 렌즈(SDT — 설계 점검용, 보장 아님)**
- 자율성: 의미 있는 선택이 있나 · 유능감: 실력 성장을 느끼나 · 관계성: 무엇과 연결되나

## Phase 3.5 — 깊이 파기 ⭐ (여기서 "띡 끝"을 막는다)
> 재미 포인트를 정했으면 **바로 만들지 말고** 이걸 먼저 캐낸다. 답은 `FUN-DEPTH.md`로.
> 사용자가 "이런 게임 만들래" 하면 **가장 먼저 물어야 할 묶음**이 이것이다.

**A. 층 파기 — 표층에서 멈추지 않게** (한 층씩 순서대로)
1. **표층(감각):** 그 순간 플레이어는 무엇을 **보고/듣고/느끼나**? 무엇이 그걸 기분 좋게 하나?
2. **중층(판단):** 그 감각으로 **무슨 결정**을 하나? 결정이 갈리는 순간이 있나?
   *(없다면 → 그냥 이펙트일 뿐, 메카닉이 아님)*
3. **심층(숙련):** 10번 하면 **뭐가 늘어나나**? (반응? 지식? 읽기? 자원관리?)
   *(늘 게 없다면 → 금방 질림)*
4. **메타(이야기):** 플레이 후 친구에게 **말할 만한 순간**이 나오나? 어떤 종류?

**B. 긴장 파기 — 재미의 엔진**
- 이 재미에서 플레이어가 **동시에 원하지만 둘 다 못 가지는 것**은? (정보vs무지, 위험vs보상, 속도vs정확…)
- 그 긴장이 **가장 팽팽해지는 순간/조건**은? → *변주 축 1순위*

**C. 실패 파기 — 재미가 죽는 법**
- 이 재미가 **지루해진다면 왜**일까?
- 플레이어가 **한 가지만 반복해도 이기는** 방법이 있나? (지배 전략)
- 실력이 결과에 **영향 없다고 느껴질** 수 있나?
→ 각 답을 **반증 지표**로 바꿔 자동 감지에 넣는다.

**D. 검증 우선순위**
- 이 중 **가장 불확실한 층**은? → 그 층을 겨냥해 **4레벨 변주**를 설계한다.

**E. 장르 팩 필수 질문 (Phase 2.5에서 고른 팩)**
- `GENRE-PACKS.md`의 해당 팩 **필수 질문 4개**를 지금 던진다. (예: 슈터→TTK·정보획득·재진입·비대칭)
- 답 → `systems/`의 규칙·공식 · `FUN-HYPOTHESIS`의 지표 · 4레벨 **변주 축**으로 배분

**산출:** `spec/FUN-DEPTH.md` D-NN (4층·긴장쌍·실패모드·층별 축) + 팩 답변
→ 이어서 `FUN-HYPOTHESIS.md` H-NN(지표는 팩의 "지표 후보"에서 선별) 작성.

## Phase 4 — 기둥과 경계
- **디자인 기둥 3~4개** — 모든 결정의 판단 기준 → GDD §0 확정 프레임
- **안티 기둥** — 이 게임이 **의도적으로 하지 않는 것** → 스코프 방어

## Phase 5 — 플레이어 & 스코프
- 이 게임을 **사랑할** 사람은? / **아닌** 사람은? *(Bartle 유형은 원래 MUD 대상 — 적응해 사용)*
- MVP 경계: 없으면 게임이 성립 안 하는 최소 기능은?
- **UEFN 실현가능성** ⭐ → `UEFN-FEASIBILITY.md`로 판정 (인테이크 직후 필수)
  - 핵심 메카닉 3~5개를 뽑아 🟢/🟡/⚫/🔴 등급
  - **🔴가 코어면 기획 변경** — "같은 재미를 다른 수단으로"(예: 조준점색🔴 → 심박음+화면틴트🟢)
  - 🟡은 **대체 설계 확정**, ⚫(GUI 수동)은 별도 티켓+정지게이트
  - 막힌다고 단정 전에 `engine_devices`로 검색 (디바이스 1119개 중 답이 있을 수 있음)

## Phase 6 — 디테일 수준(티켓 해상도) ⭐
사용자에게 **직접 확인**하고 `DECOMPOSE.md`의 기본값으로 삼는다.
- 티켓 1개는 얼마나 커야 하나? (권장: **한 번의 검증 사이클로 끝나는 크기**)
- 수치·공식을 **미리 확정**할까, **플레이테스트로 튜닝**할까?
- 어디까지 자동 진행하고 어디서 물어봐야 하나? (정지게이트 강도)

- [ ] 4개 루프 각각의 **재미 원천**
- [ ] **깊이(Phase 3.5)**: 4층 중 3층 이상 · 긴장쌍 · 실패모드 3개 → `FUN-DEPTH.md`
- [ ] 기둥 3~4 + 안티기둥
- [ ] MVP 경계 · **UEFN 실현가능성 판정**(RED 없음 or 대체설계 확정) → `UEFN-FEASIBILITY.md`

   쓰고, `DECOMPOSE.md`로 4레벨 변주와 티켓을 배분한다.
