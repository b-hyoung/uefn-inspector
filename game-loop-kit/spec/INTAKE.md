# INTAKE — 게임을 캐내는 질문지

용도: 빈 `spec/`을 채우기 위해 무엇을 얼마나 물을지 정한다. 답 → `GDD.md`(무엇/왜) → `systems/`(규칙) → `DECOMPOSE.md`(티켓).
출처: Claude Code Game Studios 브레인스토밍 워크플로(MIT)를 적응. MDA·SDT는 설계 렌즈이지 재미의 증명이 아니다.

## 원칙
- 한 번에 하나씩 대화한다. 체크리스트 낭독 금지.
- 게임보다 사람(취향·감정)을 먼저 묻는다.
- 답이 설계를 바꾸는 질문만 한다. 뻔한 것은 기본값으로 정하고 통보한다.
- 질문은 여기(①)와 ② DOR까지만 한다. 루프 착수 후에는 묻지 않는다(LOOP 규칙 0).

## Phase 1 — 창작 발견 (사람 먼저)
- 몰입했던 순간과 그 감정을 만든 것 → GDD §핵심재미 · 늘 원했지만 못 받은 판타지 → §Core Fantasy
- 오래 한 게임 3개와 계속하게 만든 것 → §레퍼런스 · 좋아하는/피하는 장르 → 안티기둥 · 도전/휴식/이야기/표현 중 택1 → MDA 미학
- 실무 제약(묶어서): 원하는 경험 · 개발 기간 · 개발 경험 → 스코프·티켓 크기
산출: Creative Brief 3~5문장.

## Phase 2 — 컨셉
한 줄 피치(10초 테스트) · Core Verb(가장 많이 하는 동작 1개, 모든 티켓의 기준) · Core Fantasy · Unique Hook("X 같은데 게다가 Y") · 가장 큰 리스크(프로토타입 티켓 후보) → GDD §1·§2

## Phase 2.2 — 형태 적합성 (컨셉 직후 판정)
`UEFN-FEASIBILITY.md` 0단계 표로 판정한다.
- 🟢 3D 슈터·생존·파쿠르·탐험 → 진행
- 🟡 2D·턴제·카드·리듬 → UEFN식 번역을 먼저 확정하고 그 번역본으로 진행(예: 2D 횡스크롤 → 고정 사이드 카메라 + X축 제한. 픽셀아트 불가)
- 🔴 RTS·클릭커·대규모 오픈월드 → 정직히 말하고 사용자가 결정한다. 억지로 진행하지 않는다.
- 흉내의 비용을 숨기지 않는다("2D 됩니다"가 아니라 "2D처럼 보이고 X를 포기한다").
→ 확정 형태를 `GDD.md §0`에 기록.

## Phase 2.5 — 장르 팩 선택
`GENRE-PACKS.md`에서 가장 가까운 팩 1~2개(하이브리드는 주/부 확정). 없으면 가장 가까운 팩 + 공통 질문으로 시작하고 새 팩을 추가한다.
공통 질문(팩 전에 항상): 승패·종료 조건 / 세션 길이 / 실패 시 잃는 것 / 인원 구조(솔로·협동·대전·비대칭 → 4레벨 인원 축) / 정보 구조(완전·불완전).
장르는 답이 아니라 질문의 안내자다. 관습 수치를 값으로 가정하지 않는다.

## Phase 3 — 코어 루프 (재미가 어디서 오나)
- 30초 루프: 코어 액션의 손맛과 그것을 만드는 것(오디오·시각 juice·타이밍·전술 깊이) → systems 수용기준
- 5분 루프: "한 판만 더"가 발동하는 지점, 어떤 선택을 하는가
- 세션 루프(30~120분): 세션의 모양·자연스러운 종료·안 할 때도 생각나는 훅
- 진행 루프(며칠~주): 무엇이 성장하는가, 언제 끝인가
동기 렌즈(SDT, 점검용): 자율성(의미 있는 선택) · 유능감(실력 성장) · 관계성.

## Phase 3.5 — 깊이 파기 (재미 포인트 확정 직후, 만들기 전)
A. 층 파기(순서대로) — 표층(감각: 무엇을 보고·듣고·느끼나) → 중층(판단: 그 감각으로 무슨 결정을 하나. 없으면 이펙트일 뿐) → 심층(숙련: 10번 하면 무엇이 느나. 없으면 금방 질림) → 메타(이야기: 친구에게 말할 순간).
B. 긴장 파기 — 동시에 원하지만 둘 다 못 가지는 것(정보 vs 무지, 위험 vs 보상, 속도 vs 정확). 가장 팽팽해지는 조건 → 변주 축 1순위.
C. 실패 파기 — 지루해진다면 왜인가 · 한 가지만 반복해도 이기는 방법 · 실력이 무의미하게 느껴지는 조건 → 각각 반증 지표로.
D. 검증 우선순위 — 가장 불확실한 층 → 그 층을 겨냥해 4레벨 변주 설계.
E. 팩 필수 질문 4개 → `systems/` 규칙 · `FUN-HYPOTHESIS` 지표 · 변주 축.
산출: `FUN-DEPTH.md` D-NN → `FUN-HYPOTHESIS.md` H-NN(지표는 팩 후보에서 선별).

## Phase 4 — 기둥과 경계
디자인 기둥 3~4개(모든 결정의 판단 기준) → GDD §0 · 안티 기둥(의도적으로 하지 않는 것) → 스코프 방어.

## Phase 5 — 플레이어·스코프·실현가능성
- 사랑할 사람 / 아닌 사람 · MVP 경계(없으면 성립 안 하는 최소 기능)
- `UEFN-FEASIBILITY.md`로 핵심 메카닉 3~5개를 🟢/🟡/⚫/🔴 판정. 🔴가 코어면 기획 변경(같은 재미, 다른 수단). 🟡은 대체 설계 확정. ⚫은 deferred 티켓. 단정 전 `capabilities`·`engine_devices` 확인.

## Phase 6 — 티켓 해상도
티켓 크기(권장: 한 검증 사이클로 끝나는 크기) · 수치를 미리 확정할지 플레이테스트로 튜닝할지 · 종료 보고에서 받고 싶은 정보. 루프 중 질문 여부는 묻지 않는다(고정: 묻지 않음).
