# UEFN-FEASIBILITY — "그거 UEFN에서 되나?"

> **왜:** 기획을 다 하고 나서 "이거 UEFN에서 안 되네"를 발견하면 최악이다.
> **인테이크 직후 · DOR 전에** 이 문서로 걸러서, 안 되는 걸 **대체 설계**로 바꾸거나 스코프에서 뺀다.
>
> ⚠️ 아래 판정은 **이 프로젝트에서 실제로 겪은 것 + 카탈로그 실측** 기준이다(2026-09 · Fortnite 42.10).
> UEFN은 자주 바뀐다. **막힌다고 단정하기 전에 `engine_devices`로 다시 검색**하고, 근거를 갱신한다.
>
> 🔧 **중요:** 예전에 "불가"였던 여러 항목이 **uefn-inspector(오프라인 파일 파싱/패치)로 해제**됐다.
> 라이브 MCP·Python 리플렉션이 못 하는 것과, **오프라인으로 되는 것**을 구분해서 판정한다.
> (예: `@editable` 배선·디바이스 설정값 = 라이브❌ / 오프라인✅)

## 0단계 — 게임 **형태**가 UEFN에 맞나 ⭐ (기능보다 먼저)
> "2D 게임 만들래", "턴제 전략", "RTS" 같은 건 **기능 문제가 아니라 형태 문제**다.
> UEFN은 **3인칭/1인칭 포트나이트 캐릭터가 3D 월드를 뛰어다니는 것**이 기본 전제다.
> 이 전제에서 멀수록 **흉내(emulation) 비용**이 커진다.

| 게임 형태 | 등급 | 왜 | UEFN식 번역(가능하면) |
|---|---|---|---|
| 3D 슈터·생존·파쿠르·탐험 | 🟢 | 엔진의 기본 형태 | 그대로 |
| **2D 횡스크롤/탑다운** | 🟡 | 카메라 고정·이동 제약으로 **흉내는 가능**, 진짜 2D는 아님 | 고정 카메라(사이드/탑) + 이동축 제한 + 평면 레벨. *픽셀아트·스프라이트는 ❌* |
| **턴제** | 🟡 | 실시간 엔진에 턴을 **얹는** 것 | Verse로 턴 상태머신 + 입력 잠금/해제. 캐릭터는 계속 실시간이라 "대기" 연출 필요 |
| **RTS / 유닛 지휘** | 🔴 | 마우스 선택·드래그·다수 유닛 제어가 UEFN 입력·AI 모델과 안 맞음 | 재설계: 1인 지휘관 + 소수 AI 동반자, 또는 "명령 지점" 방식 |
| **카드/보드게임** | 🟡 | UI가 아니라 **월드 오브젝트**로 카드/말을 표현 | 물리적 프롭·구역·트리거로 보드를 만든다 (테이블탑 실물처럼) |
| **텍스트/내러티브 어드벤처** | 🟡 | 대량 텍스트 UI가 약점 | 오디오·환경 스토리텔링·HUD 메시지로 분산 |
| **리듬게임** | 🟡 | 정밀 타이밍·입력 지연 이슈 | 관대한 판정창 + 오디오 큐 중심 |
| **모바일식 캐주얼·클릭커** | 🔴 | 입력 모델·세션 형태가 다름 | 재설계 필요 |
| **오픈월드 대규모 시뮬** | 🔴 | 메모리·인원·지속성 한계 | 소규모 라운드로 축소 |

**0단계 절차**
1. 사용자가 말한 게임 형태를 위 표에 대본다.
2. 🟡이면 → **"UEFN식 번역"을 먼저 확정**하고, 그 번역본으로 인테이크를 계속한다.
   *(예: "2D 횡스크롤 액션" → "고정 사이드 카메라 + X축 이동 제한 3D")*
3. 🔴이면 → **정직하게 말한다.** "UEFN으로는 그 형태가 힘들다. 이 재미를 살리려면 형태를 이렇게 바꿔야 한다."
   → 사용자가 형태를 바꿀지, 다른 엔진을 쓸지 결정하게 한다. **억지로 진행하지 않는다.**
4. 번역된 형태를 `GDD.md §0 확정 프레임`에 기록 → 이후 모든 설계가 그 위에서 돈다.

> ⚠️ **흉내의 비용을 숨기지 마라.** "2D 됩니다"가 아니라 **"2D처럼 보이게 만들 수 있고, 대신 X·Y는 포기한다"** 로 말한다.

## 판정 등급

|---|---|---|
| 🟢 **GREEN** | 디바이스/Verse로 직행 | 그냥 티켓 |

## 실측된 제약 (우리가 직접 부딪힌 것)

| 하고 싶은 것 | 등급 | 실제 사실 | 대체/우회 |
|---|---|---|---|
| Verse 디바이스 `@editable` **기존 배선 변경** | 🟢 GREEN | **uefn-inspector로 오프라인 읽기·쓰기 가능** (`verse_bindings` / `set_object_ref`). UEFN 수용 라이브 검증 완료(2026-09-10). 단 **UEFN 닫고** 작업(파일 잠금) | 라이브 MCP·Python 리플렉션으로는 여전히 불가 — 오프라인 경로를 쓴다 |
| Verse 디바이스 **새 @editable 슬롯 배선 추가** | ⚫ HUMAN | 기존 배선 *변경*은 되지만, **없던 슬롯을 새로 잇는 것**은 export 추가가 필요(크기변경 쓰기 = fixup 엔진 미완) → 현재는 GUI | 필요한 슬롯을 **미리** 만들어 두고 값만 바꾸기 · 슬롯 수 줄이는 설계 |
| 디바이스 설정값(예: `Can Be Heard By`) | 🟢 GREEN | **오프라인 읽기·쓰기 가능**(`read_actor` / `set_enum`). 라이브 리플렉션은 못 읽음 | 값 후보가 그 패키지 name표에 있어야 함(없으면 GUI로 한 번 세팅 후 복제) |
| 동적 조명이 벽을 막게 | 🟡 AMBER | Verse 조명이 **벽을 통과**(Lumen 다이나믹 그림자 한계) | 벽 겹쳐 두껍게(임시) · Light Blocker 전용 지오 · 맵 구조로 시야 차단 |
| 기본 HUD 조준점 **색 변경** | 🔴 RED | 기본 조준점은 색 변경 불가 | **커스텀 UMG 위젯**(`player_ui.AddWidget`) 또는 `post_process_device`로 화면 틴트 |
| 근접무기 다양화 | 🟡 AMBER | UEFN 기본 근접 = **곡괭이/횃불 정도**(포트나이트는 총 게임) | 곡괭이 스킨·연출로 차별화 · 근접 판정은 Verse로 |
| 커스텀 3D 모델·애니메이션 | 🔴 RED | 임의 외부 에셋 임포트 제한적 | 기본 에셋 조합·프롭 재배치로 실루엣 만들기 |
| 완전 커스텀 UI | 🟡 AMBER | UMG 일부 가능하나 **새 영역·난이도 높음** | 오디오·포스트프로세스·프롭으로 정보 전달 |
| 물리/탄도 커스텀 | 🟡 AMBER | 엔진 물리 직접 제어 제한 | Verse로 판정·이펙트 대체 |
| 서버 권위 로직·외부 통신 | 🔴 RED | 외부 API·DB 없음 | 세션 내 상태로 설계 |
| 대규모 인원(수백) | 🔴 RED | 세션 인원 한계 | 소규모 라운드로 |

> 빈칸은 아직 미검증. **검증하면 이 표에 근거와 함께 추가**한다(추측으로 채우지 않는다).

## 능력별 체크 (기획을 이 축으로 훑는다)
1. **표현**(보이는 것) — 조명·이펙트·UI·모델: 커스텀이 필요한가? → 대개 AMBER/RED
2. **감각 피드백** — 오디오·햅틱·화면효과: **오디오는 강함**(GREEN), 화면효과는 post_process(GREEN~AMBER)
3. **규칙·상태** — Verse로 대부분 GREEN (변수·타이머·이벤트·팀/클래스)
4. **입력** — 커스텀 키 바인딩·제스처는 제한적(AMBER~RED). 기존 입력 재해석은 GREEN
5. **월드** — 프롭 배치·트리거·볼륨: GREEN. 지형 절차생성은 제한
6. **인원·네트워크** — 소규모 세션 GREEN, 외부 통신 RED

## 절차 (인테이크 → 여기 → DOR)
1. 인테이크에서 나온 **핵심 메카닉 3~5개**를 나열
2. 각각 위 표·체크로 **등급 판정** (없으면 `engine_devices`로 검색해 근거 확보)
3. **🔴 RED가 코어 메카닉이면** → 기획 변경. "같은 재미를 다른 수단으로" 재설계:
   - 예) *조준점 색으로 위험 표시* 🔴 → *심박음 + 화면 틴트*로 같은 정보 전달 🟢
4. **🟡 AMBER**는 대체 설계를 **확정**하고 티켓에 명시(나중에 막히면 시간 폭발)
5. **⚫ HUMAN**은 별도 티켓 + `blocked` → 정지게이트
6. 결과를 `spec/assets.md`·`GDD.md §UEFN 제약`에 기록

## 원칙
- **재미는 수단이 아니라 목적** — 수단이 막히면 *같은 재미를 내는 다른 수단*을 찾는다.
  (조준점이 안 되면 "위험을 알린다"는 **목적**은 오디오로도 달성된다)
- **가장 불확실한 것부터 스파이크** — RED/AMBER 후보는 **A레벨 전에 30분 프로토타입**으로 확인.
- **막혔다고 단정 금지** — 카탈로그 1119개 디바이스에 답이 있을 수 있다. 검색 먼저.
