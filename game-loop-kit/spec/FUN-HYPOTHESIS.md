# FUN-HYPOTHESIS — 재미 가설 (실험 루프의 출발점)

> 이 kit은 **재미 포인트 하나를 여러 레벨 변주로 검증**한다.
> 여기서 "무엇이 재미인가"와 "무엇이 관측되면 그게 사실인가"를 못 박는다.
> 가설이 흐리면 어떤 레벨을 만들어도 비교가 무의미하다.

## H-01 — \<재미 가설 이름\>

### 가설 (한 문장)
> **\<플레이어가 X를 할 때\>** → **\<Y를 느낀다/한다\>** 왜냐하면 \<Z 때문\>.

예시 형식: "어둠 속에서 소리로만 적을 추적할 때, 플레이어는 긴장 속 능동적 탐색을 하게 된다."

### 관측 지표 — **전부 자동** (루프에 사람 없음)
> 루프는 **로그 지표만으로** 지지/기각을 판정한다. 따라서 **지표 설계 = 재미의 조작적 정의**다.
> 재미를 대리(proxy)할 관측 가능한 행동을 고른다. 지표가 나쁘면 결론도 나쁘다.

**수집:** 봇/자동 플레이 또는 PIE 시뮬레이션 중 Verse가 `[M]` 태그로 출력 → `get_editor_log` 파싱.

| 지표 | 조작적 정의 | 지지 방향 | 임계값 | 수집 |
|---|---|---|---|---|
| \<예: engage_dist\> | 교전 개시까지의 평균 거리 | 낮을수록 | \<T1\> | `Print("[M] engage_dist={d}")` |
| \<예: search_ratio\> | 능동 탐색 시간 / 총 시간 | 높을수록 | \<T2\> | \<...\> |
| \<예: decision_rate\> | 단위시간당 유의미한 선택 수 | 높을수록 | \<T3\> | \<...\> |
| \<예: idle_ratio\> | 아무 입력/이벤트 없는 시간 비율 | **낮을수록**(지루함 대리) | \<T4\> | \<...\> |

**샘플 수:** 변주당 최소 \<N\>회 실행(분산 고려). 실행 간 조건 동일해야 함.

### 판정 규칙 (기계가 그대로 실행)
```
지지  := 지지방향 지표 >= <K>개가 임계값 통과  AND  idle_ratio <= <T4>
기각  := 지지방향 지표 <= <k>개 통과
애매  := 그 외  → 축 하나만 바꿔 재실험 (최대 <M>회, 초과 시 가설 재작성 필요로 보고)
```
> 임계값·K·N은 **대조군(LEVEL-A) 측정 후 확정**한다. 그전에는 상대 비교(변주 간 순위)로 판정.

### ⚠️ 자동 판정의 한계 (명시)
지표는 재미의 **대리**일 뿐이다. 루프는 "어느 변주가 지표상 낫다"까지만 말할 수 있고,
"진짜 재미있다"는 결론은 못 낸다. 정기적으로 사람이 결과를 **감사(audit)** 하되,
그것은 루프 밖의 별도 활동이다(`experiments/`의 결론을 사람이 검토).

### 변주 축 (무엇을 바꿔가며 볼까)
- **공간축:** \<좁은 미로 / 개방 / 수직 / 밀집도\>
- **규칙축:** \<감지 반경 / 이동 속도 / 정보량 / 시간 압박\>
- ⚠️ 한 실험(EXP)에서는 **가능한 한 하나의 축만** 바꾼다. 둘 다 바꾸면 원인을 못 가른다
  (그래도 바꿔야 하면 `experiments/`에 교란요인으로 명시).
