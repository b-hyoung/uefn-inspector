# 필드 리포트 — BLACKOUT 게임 루프 빌드 (2026-09-10)

> **추측 금지, 실측만.** 각 항목: 무엇이 문제였나 / 원인 / 해결(또는 현재 상태).
> 원 기록: `Desktop/projects/blackout/spec/ISSUES.md` · `tech/JOURNAL.md` · `tech/TOOLING.md`.

## 0. 배경 — 왜 이 이슈들이 나왔나

uefn-inspector를 **새 클론에서 설치**하고, 그걸 엔진 삼아 UEFN 게임(BLACKOUT: 어둠 배틀로얄,
"쏘려면 드러나야 한다")을 game-loop-kit의 루프(①인테이크→②DOR→③분해→④레벨빌드→⑤판정)로 만들었다.
④ 레벨 빌드에서 라이브 UEFN(`uefn` 리스너 :8765 · `unreal-mcp` :8000)과 오프라인(uefn-inspector)을
번갈아 쓰며 디바이스 배치·배선·설정·측정을 자동화하는 과정에서 아래가 드러났다.

핵심 목표는 **UEFN을 닫고 파일만으로 디바이스 값·배선을 바꾸는 오프라인 변주** — 라이브 리플렉션이
못 읽는 Verse-VM 값을 uefn-inspector로 읽고 쓰는 것. 이슈 대부분이 그 경로를 뚫는 과정에서 나왔다.

## 1. uefn-inspector 레포 버그 — 수정함 (워킹트리, 커밋 안 함)

### BUG-07 · `conftest.py` — 새 테스트가 skip 대신 fail
- **증상:** 픽스처 없는 새 클론에서 `pytest` → `4 failed`. `test_add_binding`·`test_rebuild_trailing`이
  `FileNotFoundError`로 실패.
- **원인:** `pytest_collection_modifyitems`의 스킵 대상이 **모듈명 하드코딩 allowlist**였고, 새 테스트 2개가 빠짐.
- **해결:** allowlist를 **소스 스캔**으로 교체 — 모듈 소스가 `fixtures`를 언급하면 자동 skip. 앞으로 추가되는
  픽스처 의존 테스트도 자동 처리. → `4 passed, 70 skipped, 0 failed`.

### BUG-08 · `bin/cli.js` — Windows에서 `claude` CLI 못 찾음
- **증상:** `node bin/cli.js doctor`가 "claude CLI not found" 오탐. `mcp` 자동 등록도 조용히 실패.
- **원인:** `execFileSync('claude', ...)`가 win32에서 `claude.cmd` 셰임을 해석 못 함.
- **해결:** win32에서 `execSync`로 인용된 커맨드 문자열 실행(`shell:true`는 `DEP0190` 경고가 떠서 회피).
  비win32 동작은 그대로.

### BUG-09 · `bin/cli.js` `ensureMcpDep` — `mcp` 버전 핀 없음
- **증상:** `pip install mcp`가 핀 없이 실행 → 2.x 설치 시 `from mcp.server.fastmcp import FastMCP`가
  `ModuleNotFoundError`(2.x에서 `MCPServer`로 개명). 이 레포·KirChuvakov 서버 **둘 다 v1 API**라 서버가 안 뜸.
- **해결:** `mcp<2`로 핀. import 체크도 `import mcp`→`import mcp.server.fastmcp`로 강화(2.x면 실패→다운그레이드).

### BUG-14 · `bin/cli.js` `findPython()` — 레포 `.venv`를 안 봄
- **증상:** Python이 PATH의 스토어 스텁뿐인 머신에서 `doctor`가 "Python 3.11+ not found" 오탐 → `registerMcp()` 중단.
- **원인:** `findPython()`이 PATH의 `python`/`py`/`python3`만 프로브.
- **해결:** 탐색 순서 = `UEFN_PYTHON` → 레포 `.venv/Scripts/python.exe`(win)·`.venv/bin/python`(기타) →
  `%LOCALAPPDATA%\Programs\Python\Python3NN`(최신 버전순) → PATH. `doctor`가 `.venv` 인터프리터를 잡음.

## 2. uefn-inspector 신규 기능 — 이 작업으로 추가 (워킹트리)

> **왜:** Verse `@editable` 슬롯이 **타 액터**를 참조하도록 오프라인으로 배선하려면 기존 `set_object_ref`
> (패키지에 이미 있는 인덱스로만 재지정)로는 부족했다. 크로스패키지 **import 추가**가 빠진 조각이었다.

### FEAT-A · `core/uasset.py` 리더 확장
- `ObjectImport`에 `outer_index`·`package_name`·`optional`·`object_number` 파싱 추가(stride 40 완전 파싱),
  `full_name` 프로퍼티, `Package.import_stride` 노출. (원래는 `class_package/class_name/object_name` 3필드만 — BUG-21 참조)

### FEAT-B · `edit/add_import.py` (신규)
- `add_import(...) -> int` : import 맵 끝에 항목 1개 추가 + name표·오프셋 전체 fixup(NameCount·ImportCount·
  ExportOffset·SoftObjectPaths·trailing·export SerialOffset), 재파싱 검증·롤백. `add_binding`과 동일 계열.
- **검증:** 게이트 파일 사본에서 기존 바인딩 재현 시 **UEFN 원본과 바이트 동일**.

### FEAT-C · `edit/wire.py` `bind_editable(...)` (신규)
- Verse 디바이스의 `@editable` 슬롯을 타 액터에 **오프라인 배선**. 형식은 `analysis/verse.py`가 이미 디코드하던 것:
  플레이스홀더 서브오브젝트 export의 **`SavedActor` ObjectProperty**를 대상 액터 import로 지정.
  Package·액터·클래스 import를 `add_import`로 갖추고 `set_object_ref`로 슬롯을 지정.
- **검증:** 실제 슬롯을 플레이스홀더로 벗겨 재배선 → UEFN 원본과 바이트 동일 / 다른 액터로 재지정 → 4바이트만 변경.
- ⚠️ **UEFN 수용은 "구조·리로드·런타임 검증"까지** — SavedActor 형식은 세션에서 `vis_range` 반영·리로드 영속 확인.
  단 name 해시는 0으로 씀(add_binding과 동일), preload-dependency 항목은 미추가.
- 테스트: `tests/test_add_import.py`·`test_wire.py`·`test_wire_gate.py` (16 passed / 80 skipped).

## 3. uefn-inspector 레포 버그 후보 — 미수정 (점검 필요)

### CAND-18 · `core/properties.py` — Verse `int @editable`을 `None`으로 디코드
- **증상:** `decode_properties`가 Verse `int` 편집값(`GunShotsToKill=2`)을 **`None`**으로 읽음. `float`은 정상(2500.0/1500.0).
  런타임 로그는 `gun_ttk=2`로 값이 실재함을 확인.
- **영향:** 오프라인에서 int `@editable`(예: TTK) 읽기 검증 불가. **쓰기(`set_scalar`)는 별도 확인 필요**.
- **다음:** `core/properties.py`의 IntProperty(또는 UE5.4 FPropertyTypeName int 경로) 디코드 점검.

### CAND-19 · `analysis/spatial.*` — 시그니처 문서 부재
- **증상:** `spatial_bounds`/`spatial_extent`/`min_spacing`/`density_grid`가 `ProjectIndex`가 아니라
  **액터(패키지) 리스트**를 받음. `build_index()` 결과를 넘기면 `TypeError`.
- **영향:** 공간 분석 호출 시 시행착오. **문서/시그니처 명확화** 필요(코드 버그는 아닐 수 있음).

## 4. UEFN 워크플로·환경 이슈 — 해결/우회 (uefn-inspector 자체 버그 아님)

### WF-01 · 라이브 Python으로 디바이스 설정을 **저장할 수 없다** → Verse `@editable`로 우회 ✅
- **문제:** `set_editor_property`로 디바이스 값을 바꿔도 메모리만 바뀌고 파일에 안 남음. `modify()`·
  `ScopedEditorTransaction` 무효, `post_edit_change`는 API에 없음. 저장 후 name표에 값 문자열 0개.
- **원인:** UEFN 디바이스는 자기 **사용자 옵션**으로 동작 → UE 원시 프로퍼티를 만지면 우회됨(리플렉션에도 안 잡힘).
- **해결:** **튜닝 값을 자작 Verse 디바이스의 `@editable`에 둔다.** 공식 `DeviceToolset.SetDeviceProperty`로 쓰고,
  uefn-inspector가 `__verse_0x…` 태그드 프로퍼티로 오프라인 읽기. 사슬:
  `WriteFile→BuildAll→PlaceDevice→SetDeviceProperty(lightRadius 2500→1200)→저장→오프라인 읽기 1200.0` 검증.

### WF-02 · 엔진 디바이스 카탈로그 부재 → `ListDeviceAssets`로 확보 ✅
- **문제:** `engine_devices` 도구가 `data/engine_device_catalog.json` 없어 실패(Fortnite 파생물이라 미배포).
- **해결:** 라이브 `DeviceToolset.ListDeviceAssets`로 **383개** 카탈로그 확보. (`execute_python`으로 AssetRegistry 직접 훑기도 가능)

### WF-03 · 세션 중 등록한 MCP가 도구로 안 뜸 → HTTP 직접 호출 ✅
- **문제:** 세션 시작 이후 `claude mcp add`한 `uefn`·`unreal-mcp`는 재시작 전까지 도구로 안 잡힘.
- **해결:** 리스너/서버가 HTTP라 **직접 POST**. `uefn` 리스너 `{"command","params"}`→`127.0.0.1:8765`(29커맨드),
  `unreal-mcp`는 MCP-over-HTTP(:8000, `initialize`→세션ID→`call_tool`). MCP 브리지 없이 동작.

### WF-04 · 자동노출이 어두운 맵을 도로 밝힘 ✅(설계 반영)
- **문제:** 조명을 다 지워도 UE 자동노출이 적응해 다시 보이게 만듦.
- **해결:** 전역 암흑엔 **노출 manual 고정 필수**. `PostProcessComponent.settings`(`unbound=True`=레벨 전역)에
  `override_auto_exposure_method=Manual`, `auto_exposure_bias=-4`.

### WF-05 · 갓 배치한 디바이스는 파일에 값이 없음 ✅(정상 동작)
- UE는 **기본값과 다른 것만 직렬화**. 방금 스폰한 디바이스를 오프라인으로 읽으면 구조만 있고 값 없음.
  "비어 있음 = 고장"이 아니다. → **오프라인 변주 대상은 한 번 비기본값으로 써둘 것.**

### WF-06 · uefn-inspector에 생성 함수 0개 ✅(설계상 정상)
- `edit/`는 `set_*`·`add_binding`·`patch`·`resize`뿐(고치는 도구). **최초 배치는 라이브** `DeviceToolset.PlaceDevice`.

### WF-10 · `install-skills.ps1`이 한글 파괴 ✅(소멸)
- **문제:** PS 5.1이 `Get-Content -Raw`를 CP949로 읽어 UTF-8 한글 모지바케 + `Set-Content -Encoding utf8`이 BOM 부착.
- **해결:** 업스트림이 `bin/cli.js`(Node, UTF-8) 래퍼로 교체하며 구조적으로 소멸.

### WF-11 · 리스너 수동 실행 필요 ✅
- `uefn_listener.py`+`init_unreal.py`를 프로젝트 `Content/Python/`에 복사 → UEFN 기동 시 :8765 자동 시작(실측).

### WF-12 · `DeviceToolset` 속성 도구는 **자작 Verse ScriptDevice에만** 먹음 ⭐
- **문제:** `Set/Get/ListDeviceProperties`가 스톡 크리에이티브 디바이스는 `PlaceDevice`로 정식 배치해도 거부
  (`not valid ScriptDevice`). PostProcess·PointLight 둘 다 확인.
- **결론:** **모든 튜닝 값을 자작 Verse 디바이스의 `@editable`에 둔다.** 스톡은 배치만, 동작은 Verse로 제어.
- ⚠️ `SetDeviceProperty`의 `value`는 **JSON 문자열**(오브젝트는 `{"refPath":"..."}`).
- ✅ 반면 `AddEventBinding`(스톡끼리 이벤트→함수)은 완전 자동화. 단 바인딩은 **타깃** 디바이스에서 조회(`ListEventBindings(target)`).

### WF-15 · Verse `@editable` 슬롯 → 스톡 디바이스 배선 ✅(SavedActor 형식)
- **문제:** 5경로 실패 — 툴셋 타입거부 · 액터/서브오브젝트 직접 대입 거부 · `new_object` 래퍼(저장은 되나
  **리로드 시 해석 실패→플레이스홀더 복귀**, 세션 `vis_range=0`).
- **해결:** 정답은 저장소 안에 있었다 — `analysis/verse.py` 도크스트링대로 **플레이스홀더 export의 `SavedActor`**에
  액터 대입. 5슬롯 배선·저장·**리로드 영속·런타임 동작**(`vis_range=2500`, `guard_spawned×4`) 검증. GUI 불필요.
- → 이 형식이 §2 FEAT-C `bind_editable`의 근거.

### WF-22 · `Play command is not currently available` = **Valkyrie 로그아웃** ✅
- **원인:** `is_valkyrie_logged_in()=false`(전조 `ossv2_auth_token_refresh_failed EOS_NotFound`).
  프로젝트는 열려 있음 → 리로드 탓 아님. **실패한 세션 쿠킹이 로그아웃을 유발**하는 재발 패턴.
- **해결:** 재로그인 API 없음 → **런처 URI 재기동**(exe 직접은 1회용 exchangecode라 불가):
  `com.epicgames.launcher://apps/fn%3A1e8bda5cfbb641b9a9aea8bd62285f73%3AFortnite_Studio?action=launch&silent=true`
  → 런처가 새 코드 발급 → 홈 화면 **MyProject 타일 더블클릭**(창 원점 +640,+345, DPI-aware; 단일 클릭은 선택만)
  → 리스너 ~180s → 로그인 복구. 자동 스크립트에 로그인 체크+재기동 내장. 검증됨.

### WF-23 · `unreal.Rotator` 위치 인자 순서 = **(roll, pitch, yaw)** ✅
- **문제:** `Rotator(0, yaw, 0)`은 yaw가 아니라 **pitch**. 벽·커버·카메라가 잘못 회전(벽이 눕고 카메라가 하늘).
- **해결:** 항상 키워드 — `unreal.Rotator(roll=0, pitch=p, yaw=y)`. `Vector(x,y,z)`는 순서대로 OK.

### WF-24 · 트랜스폼만 바꾼 OFPA 액터가 저장에서 빠짐 ✅
- **문제:** `set_actor_rotation`만으로는 액터 패키지가 더티로 안 잡혀 `save_current_level`/`save_dirty_packages`가 건너뜀
  (메모리 OK·파일 옛값). `mark_package_dirty`는 API에 없음.
- **해결:** `EditorLoadingAndSavingUtils.save_packages([actor.get_outermost()], only_dirty=False)`로 명시 저장.

### WF-25 · `UEFNValidation: Disallowed reference` — 세션이 참조할 수 있는 에셋 제한 ✅(되돌림)
- **문제:** 비주얼 패스에서 넣은 환경 메시 5종(`sm_Creative_fac_barrel`·`CP_Coliseum_ExtWall_Column_01`·
  `CP_Ground_Plane`·`CP_Prop_ShippingContainer_01`·`CP_S_JungleTemple_Wall_03`)이 `StartSession`에서
  **`Disallowed reference`**로 거부(모달 "플레이할 수 없음"). 에디터엔 보이지만 아일랜드 쿠킹 금지.
- **함의:** **에디터 렌더 성공 ≠ 세션 유효.** `spawn_actor(StaticMeshActor, 임의 메시)`로 아트 넣는 접근은 세션에서 무효.
  허용 확인된 메시: `/Game/Creative/Devices/Destruction_Object/Meshes/S_Cube`(세션 4~7 통과). 진짜 아트는 프롭 갤러리 필요.
- **해결:** 비주얼 액터 98개 제거 → S_Cube 그레이박스 16벽 복원·저장. 오프라인 스캔으로 disallowed 참조 0 확인.
  ⚠️ OFPA 삭제는 저장 후에도 외부 액터 파일이 남을 수 있으니 디스크 스캔으로 검증할 것.

## 6. 재발 함정 — 한 줄 요약 (다음에 시간 아끼려면)

- 디바이스 설정은 **자작 Verse `@editable`**에만 오프라인으로 쓰인다. 스톡 값은 프로그램으로 못 바꿈.
- `@editable`→타 액터 배선 = **플레이스홀더 export의 `SavedActor`** 형식. (읽기 경로 `analysis/verse.py`가 정의)
- 디바이스는 `spawn_actor`가 아니라 **`DeviceToolset.PlaceDevice`**로 배치해야 툴셋이 다룸.
- `unreal.Rotator`는 **(roll, pitch, yaw)** — 키워드 필수.
- 트랜스폼 편집 저장은 **`save_packages([a.get_outermost()], only_dirty=False)`**.
- 세션에서 쓸 메시는 **허용 목록**만(에디터에 보여도 `Disallowed reference` 가능). S_Cube는 통과.
- `Play command not available` = **로그아웃**. 런처 URI 재기동 + 타일 **더블클릭**.
- 세션 실패한 쿠킹은 **로그아웃을 유발**한다.
- `get_editor_log(last_n=, filter_str=)` — `lines` 아님. `[M]` 태그로 지표 방출→파싱.
- UE는 **기본값과 다른 것만 직렬화** — 변주 대상은 한 번 비기본값으로 써둘 것.
- 세션 기동 ~80–96초. 반복 실행은 한 세션에 여러 판 돌리도록 설계.
- 봇 자동 구동은 **가드를 교대로 두 팀에 배정**(`fort_team_collection.AddToTeam`)하면 상호 적대→교전 발생.
