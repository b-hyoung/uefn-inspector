## UEFN MCP 자동화

### ❌ 절대 하지 말 것
- **`SceneTools.find_actors` 호출 금지** — 씬 50만 오브젝트 스캔으로 에디터가 완전 정지(30분). 재시작 외 복구 불가에 가까움.
- **대량 배치·삭제를 연속 호출하지 말 것** — `remove_from_scene`도 몰아서 부르면 프리즈. 소량씩, 간격(0.2~3초)을 둘 것.

### ✅ 반드시 할 것
- **배치할 때 반환 refPath를 즉시 JSON 원장에 기록.** 나중에 삭제·수정하려면 이것 없이는 액터를 찾을 수 없다(그리고 찾으려다 위의 프리즈를 만난다).
- **배치 후 `save_actor`** — 안 하면 OFPA 파일이 안 생겨 오프라인 도구에 안 보인다.
- **전수 조사·검증은 uefn-inspector 오프라인으로.** 에디터 부하 0, 프리즈 없음, 에디터 켜져 있어도 됨(단 저장된 시점 기준).

### 세션 다루기
- 상태 판단은 **`GameState`**로 (`CanStart` → `StartGame` → `Running`). `SessionStatus`는 신뢰 불가(UpdatingContent에서 멈춤).
- `StartSession`/`StartGame`은 90초 이상 블록 → 백그라운드 잡 + 폴링.
- 실행 중 Verse 핫푸시 불가 → `StopGame` → `StartGame`.
- **서버측 `Print`는 에디터 로그**에 남는다(클라 로그 아님).
- EOS 인증이 1~2시간마다 만료 → 장시간 작업 시 주기적 재로그인.

### 디바이스 프로퍼티
- **빌트인 디바이스**: `SetDeviceProperty` 아예 불가("not valid ScriptDevice"). 이벤트 배선(`AddEventBinding`)은 가능.
- **Verse 디바이스**: 프로퍼티 노출은 되지만 **스칼라·enum만 실용적**. 오브젝트 참조(디바이스 간 배선)는 타입 검증에서 거부됨 → GUI 필요.
- `AddEventBinding`은 `returnValue:null`이라 성공 여부를 알 수 없음 → **타깃 디바이스**에 `ListEventBindings`로 확인(소스로 조회하면 빈 배열).

## uefn-inspector (오프라인 도구)

**강점 (이번에 실제로 쓴 것)**
- 배치 검증: `build_index` + `inspect_actor`로 좌표 디코드 → 아레나별 구성 대조. 76~206액터를 에디터 부하 없이 검증.
- 중복·잔여 탐지: 좌표 기준으로 겹친 액터, 아레나 밖 잔여물 발견 (실제로 문제를 두 번 잡아냄)
- `@editable` 배선 읽기: 슬롯 존재 여부와 값(null 포함) 확인

**한계 (실측 확인)**
- **읽기 전용에 가깝다.** 맵을 짓는 것(새 액터 배치)은 불가 — 라이브 MCP 필요.
- 쓰기는 **동일 크기 치환만**. 프로퍼티 신규 추가·import 추가처럼 크기가 변하는 편집은 fixup 엔진 미완성.
- 그래서 **최초 @editable 배선은 불가**, 기존 배선 *변경*만 가능.
- `engine_devices`는 카탈로그 파일이 없으면 사용 불가(라이브 `ListDeviceAssets`로 대체).

## Verse

| 함정 | 정답 |
|---|---|
| `int / int` | **rational** 반환. 정수 연산은 제곱거리 등으로 나눗셈 회피 |
| 조건 표현식 | `if (c) **then** A else B` — then 필수 |
| if 조건에서 함수 호출 | `<computes>` 필요. **단 객체를 생성하는 함수엔 붙일 수 없음** |
| `loop` 본문의 비교 연산 | 실패 가능이라 직접 불가 → `if` 조건으로 |
| `vector3` / `IdentityRotation` | `/UnrealEngine.com/Temporary/SpatialMath` (`/Verse.org/SpatialMath` 아님) |
| 전역 상수 이름 | 파일 간 충돌 주의(`TICK` → `HUB_TICK`). `Err`는 예약 충돌 |
| `OnBegin` 실행 시점 | **플레이어가 섬에 입장해야** 실행됨. 로딩 중엔 로그 안 나옴 |
| `continue` | 예약어지만 미구현 → `if` 중첩으로 대체 |

## PowerShell (자동화 스크립트)

| 함정 | 정답 |
|---|---|
| `switch` 반환이 **배열** | `[int](@($x)[0])`로 강제 스칼라화. **문자열 보간에선 정상처럼 보여** 발견이 어렵다 |
| 함수의 미포획 출력이 반환값에 섞임 | `return` 명시 + 파싱은 정규식 헬퍼로 분리 |
| 한글 주석 .ps1 | PS 5.1이 ANSI로 읽어 깨짐 → 영문 주석 또는 인라인 실행 |
| JSON 파라미터 | 오브젝트 참조는 `{"refPath":"..."}` 형태여야 함(문자열 직접 전달 시 "not valid JSON") |

## 프로세스 교훈 (가장 중요)

1. **"플레이어가 그 콘텐츠에 어떻게 도달하는가"를 먼저 설계하라.**
   맵 4개를 300m 간격으로 지어놓고 이동 수단을 나중에 붙이려니, 스폰은 랜덤이고 걸어갈 수도 없는 상태가 됐다. 이동·시작점이 맵보다 선행 요건이다.

2. **"맵"과 "게임"을 구분하라.**
   지오메트리·조명·프롭·스위치를 다 만들어도 **규칙·승패·목표가 없으면 게임이 아니다.** 사용자 지적으로 뒤늦게 게임 규칙(목표·타이머·승패)을 넣었다.

3. **코어 재미를 먼저 검증하라.**
   이 게임의 코어는 "예측 지배감"(유도→역습)인데, 그걸 구현하는 데 필요한 배선이 막혀 있다는 걸 **맵을 다 짓고 나서** 알았다. 가장 불확실한 것부터 스파이크했어야 했다.

4. **문서의 능력표를 먼저 읽어라.**
   `@editable` 신규 배선이 "⚫ HUMAN(GUI)"라고 uefn-inspector 능력표에 **이미 적혀 있었다.** 읽었으면 4번의 실패 시도를 아꼈다.

5. **툴 반환값을 맹신하지 말고 독립 검증하라.**
   `remove_from_scene`의 `false`가 실패가 아니었고, `AddEventBinding`의 `null`은 성공이었다. 반영 지연(수십 초~수 분)까지 고려해 오프라인으로 재검증해야 한다.
